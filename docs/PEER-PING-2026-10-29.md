# Peer ping and connectivity repair, October 29

## Causes and scope

Draper700 (`172.9.0.95`, SSH user `draper`) had no running XPN connection.
Its old 0.1.0 client dialed `172.9.0.108` because Route10 DNS overrode
`alta.jeffhansen.com`. The user corrected DNS; a fresh systemd-resolved query
returned `138.68.255.92` and HTTPS returned 200. The user reconnected and confirmed
LAN ping to `.5` and iPhone `.4`. The user also disabled Route10 S2S masquerade:
its translated source `192.168.98.2` had not matched Alta's home-subnet rule.
The assistant made no Route10 configuration changes.

Client-to-client ping was separately blocked in both native packet filtering and
the server forwarding firewall. The new `allowClientPing` boolean is server-only,
default false, backward-compatible with saved policies, and independent of the
home-forwarding switch. It permits ICMP echo requests and established replies
between `10.77.0.2–254`. Other peer protocols, invalid/spoofed source addresses and
XPN-initiated home traffic stay blocked. Client routing policy still applies.
No profile, invitation or key changes are required; existing clients do require
an updated native binary because the old binary rejects peer ping itself.
